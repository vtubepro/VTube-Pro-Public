# Live2D → 3D anime avatar

A VTuber brings the Live2D model they own (the folder they load into VTube Studio) and VTube Pro builds a 3D anime
avatar from it: a normal VRM + `profile.json` that tracks, blinks, talks (carved mouth, ARKit / viseme shapes) and has
spring hair. Everything runs locally; nothing is uploaded.

- **In the studio (beta.12)**: a Live2D model you import becomes a Pro2D avatar (`.vtp2`, docs/RIG2D_FORMAT.md; the
  Live2D files are not kept). Its 2D panel has **Make a 3D version with my AI**: your own Claude / ChatGPT app runs
  this pipeline through VTube Pro (the `.vtp2` adapter below), checks the result and iterates in your Blender. The
  whole feature, its checklist and the AI's recipe: **[PRO2D_TO_3D.md](PRO2D_TO_3D.md)**. There is no separate
  "Live2D → 3D" button or `/api/live2d/*` route (an earlier version of this page described one that never shipped).
- **CLI** (a Live2D folder you still have): `python tools/live2d_to_3d.py <folder | *.model3.json | model.zip> <out_dir>
  [--sex auto|female|male] [--hair-mode auto|down|ponytail|twintails] [--name N] [--id ID] [--no-hair]
  [--stage-only analyze|design]`
- **CLI** (a Pro2D avatar): `node --import tsx tools/pro2d_bundle.ts export <avatar.vtp2> <bundle>`, then
  `python tools/live2d_to_3d.py <bundle> <out_dir> --vtp2 [--overrides o.json] [--mode full|hair|springs|profile --prev
  <previous out_dir>] [--base <your own VRoid base .vrm>] [--progress p.json]` (`VTP_PRO2D_EVAL` = the evaluator command;
  with `--vtp2` / `--base` / `--builtin-bases` the bases are VTube Pro's own bundled Mirelle and Kairo,
  `blender/to3d/builtin_bases.json`).

Requirements: Python 3 with numpy, Pillow, scipy, opencv (VTube Pro's "3D toolkit" installs its own, PRO2D_TO_3D.md);
Blender 4.2+ for the hair stage (run at IDLE priority; set `VTP_BLENDER_LOCK=<dir>` to serialise Blender runs between
parallel jobs); a base body: VTube Pro's own bundled bases (Mirelle, Kairo; already included in every install), the
CC0 VRoid classic samples (`tools/vendor/vroid`, source checkouts, the plain Live2D CLI), or the user's own VRoid base.

## Legal (read before shipping or changing this)

- **No Live2D code is used or shipped.** Cubism Core is proprietary (no redistribution under open-source licences,
  "Expandable Applications" such as avatar / streaming apps need Live2D's approval). The `.moc3` reader
  (`blender/live2d/moc3.py`) is an independent implementation written from the OpenL2D *MOC3 format specification*
  (moc3ingbird, FDPL) and the MIT-licensed moc3-rs deformer maths. Decompilation-derived readers (py-moc3,
  moc3-reader-re) must not be used or copied.
- The performer must **own the model or have permission** to convert it (the 3D-version drawer requires the tick):
  commission terms and the rigger's Cubism Editor licence can restrict derivative works.
- Open question for the maintainer: Live2D's Editor / Core licences forbid using Output Files "with middleware that
  compete(s) with" Live2D. A one-off converter is not a Live2D runtime, but decide before a public release whether
  the moc3 reader ships (the alternative is a screenshot / PSD-only route).
- **Official Live2D sample models may be converted for local testing only.** The Free Material License forbids
  selling, distributing or *making public* 3D models made from them (4.1.7), and Hiyori / Miara / Mark / Natori have
  extra restrictions. Never commit, ship, stream or post converted samples.

## Pipeline (blender/live2d/)

| stage | file | what it does |
|---|---|---|
| read | `model3.py`, `moc3.py`, `render.py`; a Pro2D avatar: `vtp2.py` (the same surface, poses from `tools/pro2d_bundle.ts`, the runtime's own evaluator) | model3.json + JSON side files; clean-room moc3 reader (v1–v6) + puppet evaluator (keyform blending, warp / rotation deformers, glue, blend shapes, draw-order groups, masks); software rasteriser for any parameter pose |
| analyze | `analyze.py` | what every art mesh is (standard Cubism parameters that move it, part / mesh names in EN + JP from cdi3, then colour / position), landmarks (eyes, brows, mouth, chin, crown, face widths), colours (skin, hair base / shade / light / root→tip / streaks, iris top / mid / bottom, sclera, lash, brow, blush, mouth), outfit bands (top incl. open-jacket inner, skirt vs pants, legwear, shoes, sleeves) |
| design | `design.py` | measurements in IPD units vs the chosen CC0 VRoid base → face_kit preset: sex (eye opening, lower-face length, brows, iris shape), base (hair length / hood), eye size, chin, face width + jaw from the drawn contour (cheek width halfway eye→chin, jaw at 80 %, vs the same rows measured on the base), colours (skin pushed warmer for MToon), VFace brow / blush / nose / mouth |
| eyes | `eyefit.py` | the model's own eye design: each drawn eye rendered per layer (white / iris / highlight / lash, clipping applied) and measured → face_kit `anime_eyes` preset (female / male, blended by the sex score) with opening height / tilt / lid peak + roundness, iris width / aspect / tuck, iris gradient + pupil, highlight layout, lash thickness / wing / colours overridden → VFace iris / highlight / lash params, creator `eyeTilt` (relative to the base's own corner tilt), and the opening that `faceadj` bakes. `l2d/eyes_fit.png` shows the fitted eye |
| build | face_kit `anime_face` | VRoid base + drawn face repaint + proxy normals + MToon + ARKit 52 |
| face | `faceadj.py` | the DRAWN LID LINE as the eye's shape (`lid_template`): eyefit's upper-lid curve (rise over the corner line at 24 columns) + the drawn iris tuck (share of the iris under the lid) -> per eye column the share of the VRoid close morph that brings the base's lid onto the drawn line, close / blink morphs shortened per vertex (a blink still closes); a uniform narrowing (`narrow_eyes`) only when no curve was measured; the lower lid likewise onto the drawn lower line + lower iris tuck with the squint morph; pointed teeth drawn in any of the character's drawings (the main input or `--ref` drawings: `image2d.teeth_from_drawing`, an open mouth with 3+ tooth shapes in a row) -> `shark_teeth`: the drawn teeth strip of the mouth texture re-edged into points, the flat teeth planes enlarged (still flat, drawn); the drawn neutral mouth LINE painted as drawn (VFace `skin.mouthDrawn`: its width, stroke, corner lifts and ink colour); a clean flat skin over the whole face out to the ears (`skin.flattenFade`: no lighter cheek band); the drawn neutral mouth line (`mouth_shape`: smile curve and each corner's lift, Live2D front crop or the drawing itself) baked as a rest smile or a one-sided smirk; ears tucked in |
| outfit | `garment.py` | the drawn front of the outfit projected onto the garment FRONTS (tops, bottoms, shoes, body skin where the art shows cloth), registered by chin / shoulder / feet + torso widths; drawn long sleeves painted on the arms, stockings on the legs, skirt length stretched to the drawn hem; a straight / pencil skirt (drawn hem ≈ hip width) re-seats the base skirt on a smooth tube around the hips and legs with tube normals, skirt spring weights moved to the hips; sleeves that are the jacket's shaded colour take the jacket's lit colour; neck accessory recoloured (and the drawn scarf / ribbon pattern projected onto it) or hidden; a drawn collar / hood wider than the base's is widened to the drawn silhouette between shoulders and chin |
| hair | `hair2d.py`, `hair_blender.py`, `assemble.py`, `hair.py` | Live2D hair drawables → lock guides (tips / valleys along each drawable's lower edge, solid fringes split into locks, width profile, **depth from the rig's own head turn**: `x(ParamAngleX +30) − x(−30)` per vertex, calibrated eyes vs head centre), hairstyle detection (down / ponytail / twin tails, back length, front-hanging locks) → anime_hair clumps on the real head (front / back surface rays, volume shell, root continuation up to the hairline, fringe under-layer, invented back of the head: staggered rows of broad locks over a volume dome sized from the drawn silhouette, their hanging parts kept at a monotonic distance from the head axis (no kinks at the ears), or pulled-back flow to the tie; anatomical hairline: sideburns ~ eye level, nape ~ mouth level, arching over the ears for tied styles; drawn drills = one twisted ribbon; locks are tapered pointed ribbons with an S and a little twist, the invented back is
four depth rows (top rows swept by the drawn crown's sideways shift and lifted off the dome, the lowest row a darker
under-layer), a solid fringe fill under the whole drawn fringe (strips interpolated between the drawn locks) down to the drawn fringe's solid line between the tips (`hair2d.fringe_envelope`, a morphological opening of the fringe's lower edge), so the forehead only shows between the tips; upswept crown / side flicks from spikes of the drawn hair outline (`hair2d.outline_flicks`); each drawn hair region cut into its LOCKS along the art's own ink lines, every lock's width measured across its spine and its split tips from its own lower edge (the 3D lock takes that contour: body width, monotone taper to a point, 1-3 tips; fill strips end in soft points); interior strand ink strokes along every lock's own UV spine, as many (0-2) as the drawn hair's thin-line density calls for; rising crown locks wherever the drawn outline rises above the fitted dome (`silfit.crown_locks`); face-framing side locks drawn across the cheek edge lie in front of the cheek and grow out from under the fringe; lock centre lines traced through the drawn strand DIRECTION field (`hair2d.stroke_field`: structure tensor of the art's luminance, `trace_strand` from each tip up to the root), so swept fringes sweep; drill / ringlet curls as ONE clean round tube (anime_hair `Clump.round_back`: a closed elliptic section) down the drawn tail axis -- the axis smoothed first (the drawn axis zig-zags with the curls, a tube bent that tightly folds into knots) and wound as one gentle coil, a rounded swell with a waist per drawn curl, a soft point, one twist per curl so its ink edges wind round it as the drawn spiral lines (`hair_blender.drill_coils`); CLEAN CEL hair shading: no per-lock shadow band or root darkening, crisp ink edges, one crisp angel ring only on locks that cross the ring height, the light / shadow shapes from the smooth mass normals + toon ramp; ONE angel ring round the head at a fixed height (anime_hair `Clump.ring_z`: each hanging lock's texture v is remapped so the ring lands where the lock crosses that height, instead of a band at the same fraction of every lock); a forehead coverage repair (`hair_blender.forehead_cover`: every front clump projected into the drawing's frame with its edge-on-corrected width, columns still showing skin between the valley line and the hairline closed with a blunt strip); dyed tip colour only on locks that end below the chin; a side tail drawn beside the face eased out beside the neck; built with anime_hair `style='drawn'`: per-clump
shell winding + every lock ring shaded with the smooth mass normal, see blender/anime_hair/README.md) → proxy normals, cel atlas in the model's colours, ink hull, spring chains → replaces the VRoid hair in the VRM (fringe / side chains without head colliders so they stay on the face) |
| turnaround (optional) | `turnaround.py` | `--turnaround <dir>` (front / three_quarter / side / back images or one sheet) or `--turnaround auto` (runs the generator command the user configured in `VTP_TURNAROUND_GEN`, e.g. their own image-generation account; nothing is uploaded otherwise). Cached per model (moc3 + texture hash) in `<out>/l2d/turnaround/`. Measured on hair / garment silhouettes only (face stays drawn, eyes stay the moc3 fit): back hair length (back view), nose-to-back-of-hair depth (side view -> dome back volume), back hair width (side volume), tips along the back hem (back row density), back-side hair colours. Without it the pipeline is unchanged |
| silhouette fit | `silfit.py` (+ `hair2d.drawn_masks` / `label_masks`) | ANALYSIS BY SYNTHESIS in Blender, MULTI-VIEW + FLOW: the front pose AND the model's own +-30 head turns (rendered at +-20 deg orbits, which turn goes with which orbit decided by the cost) as targets, plus the drawn strand direction field (structure tensor of the hair art, doubled angle + coherence) as a flow cost on every lock's projected spine; each lock may also turn about its root; drawn tails may move in depth; the dome gets a sideways crown lean. The drawing's visible hair / face / eyes (a label composite in the model's draw order, or the drawing's regions) on a fixed IPD grid; the dome's top / left / right volume fitted first (Workbench front renders of the dome vs the drawn hair outline above the eyes), then every front lock (fringe, fill strips, flicks, side and face-framing locks, drawn tails moved as one group with their helix axis, back locks that overshoot the outline shrink / lift only) refitted by coordinate descent -- tip shift, width, drop for invented strips -- against missed drawn hair + extra hair (x2 over drawn skin, x6 over the drawn eyes); ~400 flat orthographic renders, one per changed lock, masks cached; `silfit.png` = before / after |
| turns (always) | `turnaround.turn_profile` + `hair_blender.fit_dome_to_turns` | the model's OWN turnaround: the hair silhouette at ParamAngleX -30 / 0 / +30 per height band; the far side of a turned head is the only place a Live2D model draws the side / back of the hair mass. The dome's far-side volume is least-squares fitted to it with the EFFECTIVE turn angle (a Live2D "30 deg" moves the eyes like a ~20 deg rotation) and blended with the front-view width |
| garments+ | `overlay.py` | generated garment parts the base lacks: an open hood / collar with a CONTRASTING LINING (drawn lining / rim band / outer colours + extents; the base hood and everything of the top standing around the neck removed): a STANDING HOOD SHEET swept round the neck the way a modeller would build it -- a thick rounded sheet from the neck base up and out to the rim (open at the zip, tapering shut at its ends), jaw-high and opening outward beside the neck so the drawn LINING faces the viewer, taller behind the neck and lying down the upper back where the base hood was cut, the dark shell outside; the base top's pieces under the sheet removed (a fur trim keeps the older jagged ruff); `fur_puffs` -- a spiky trim (the trim colour's outline much longer than its convex hull) becomes a continuous ruff of tufts of flat curling FLAME blades (licking outward / up, never down) round the neck, coloured by the drawn fur's own gradient (inner pixels = roots, rim = tips) (the drawn size at the front, open where the jacket opens), radial normals, root -> light tip ramp; `head_accessory` -- a mask / ornament with its own pair of eyes drawn on the head: its drawn OUTLINE (plate colour grown from between its eyes, the cranium convex, the jaw keeping the gaps between its teeth) lifted into a solid by SILHOUETTE INFLATION (a face-plate profile -- rounded rim, flat-ish middle -- with raised rounded tooth bars wherever the drawn jaw splits into teeth, textured front re-inked as flat cel colour, shallower back, closed rim) in its own frame, facing the viewer like the drawing and seated on the head's own radius at the drawn place; `choker` -- a drawn neck band (image route: a run of dark strap rows across the neck column, buckle rows bridged) as a thin band round the neck with the drawn front (buckle) on its front third; the drawn neck accessory (off-centre knotted scarf, tie, ribbon) as a thin puffed shell conforming to the chest, textured with the drawing itself, replacing the base bow / tie. Dark painted garments get a low app rim (material extras `vtpRim`) and lose the base fold normal map (no edge glare) |
| image route | `image2d.py` | a single front DRAWING instead of a Live2D model (`--image`, or any .png / .jpg input): GrabCut figure, the iris pair (compact saturated blobs at several thresholds, paired by size / level / spacing, a pale face below), the face region from the skin colour under the eyes (chin = its lowest point), hair = the head region in the hair colours, garments below the chin (outer layer = the colour on BOTH sides of the body, inner = the middle, trim = a saturated shoulder colour; a patterned inner layer (swirls, print) is kept as its drawn box and mirror-tiled over the base top's under-layer and the open-jacket column, the rest of the under-layer in its ground colour); a dark / black sclera keeps a dark lid shadow and a glowing iris; a cool (blue / lavender) skin keeps its hue unsaturated; hair locks via `hair2d.mask_locks` (the same tracer as Live2D drawables) + `crown_strands` (strands followed through the drawn direction field from seeds over the crown). The same generators then run. No depth information: layer defaults |
| profile | `finish.py` | `source: import`, provenance, reference pictures (`live2d_ref/`); also `look.vrmExposure 0.74` (the app scales every VRM MToon colour by it, default 0.62: a converted drawing's colours are already the lit colours) and `creator.signatureRest`; skin materials get `vtpShadeShift -0.5` (`faceadj.skin_shading`); optional `--signature-rest` bakes the `--ref` grin into the rest face (default off) |

Every fix found while testing is a pipeline step (AGENTS.md rule 8); nothing is hand-edited per character.

`--live-blender` builds the hair in a VISIBLE Blender window (step by step, the view orbiting the head, previews of
the traced locks, header = current step; the window closes itself and the conversion continues).

## What is and isn't recreated (honest)

Recreated well: hair colour, streaks / dyed tips, fringe shape and coverage, side locks, hair length, pulled-back vs
loose hair, side ponytails, the drawn outfit's colours and front details (lapels, trims, prints, zips, stockings,
shoes), eye colour and gradient, male / female eye shape, skin tone, spring physics.

Approximated: garment SHAPES beyond skirt length / pencil-vs-flared (VRoid base garments carry the drawn front art: a
jacket becomes the base top, a short base sleeve stays short over a painted long one, a big drawn hood becomes the base
hood), the back of the head (invented, never drawn in Live2D), strongly swept / spiky male crowns (the dome is smooth,
locks follow the drawn split but not every flick), eyes limited to what the VRoid eye parts can show (shape via the
base mesh + tilt / narrowing; iris, highlights and lash are painted), accessories other than the neck (hats,
ribbons, glasses are not modelled yet).
